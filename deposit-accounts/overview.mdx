# International deposit accounts

Open **bank deposit coordinates** and optional **stablecoin wallets** for your end-customers after vault KYC, under public Partner routes `/partner/customers/{customer_id}/accounts`.

Identity is always **`customer_id`** (`pcus_*`). See [Customers quickstart](/customers/quickstart) for create → documents → submit → approve.

This is a **separate product** from:

- African local-fiat **quote to accept** ([Quickstart](/quickstart), [Corridors](/corridors/overview)) — you may attach `customer_id` on quote when `status=approved`
- Catalog **`international_bank`** EUR/USD payin via quote to accept (a one-shot ramp, not reusable deposit accounts)

Use **one product per checkout**; do not mix deposit-account rails with a local OnRamp/OffRamp quote in the same flow.

<Warning>
**Legacy `/partner/entities/*`:** still present for older banking integrations. **New integrations must not adopt entity routes.** Further money ops (deposit-instructions, sends, book transfers, cards) will land as `/partner/customers/{customer_id}/…` facades — see [Roadmap](/customers/quickstart#roadmap).
</Warning>

## Capability matrix

Honest **Ready / Limited / Hold** for integrators (same shapes as [errors](/errors) and account statuses). Prefer the column status over marketing language.

| Job | Status | Notes |
|-----|--------|--------|
| Individual KYC (vault) | **Ready** | Wait for customer `approved` |
| Business KYB (vault) | **Ready** | Prefer single-officer path first; see [Customer KYC](/deposit-accounts/kyc) |
| Open EUR / GBP / CAD (fiat) | **Ready** | When `products.deposit_account.status=ready`, then account `active` + deposit-instructions when facaded |
| Open USDC / USDT wallets | **Ready** | When deposit product `ready` and account `active` |
| Open USD (business) | **Ready** (most) / **Limited** (e.g. KE business unconfirmed) | Poll until account `active` |
| Open USD (individual) | **Limited** | KE individuals: **USD bank not available** (other fiats OK) |
| Fiat book-transfer | **Ready** (legacy entity path today) | Customer-scoped facade **coming** — see roadmap |
| Stablecoin or inter-customer “book-transfer” | **Hold** | Product does **not** exist. Fiat book-transfer only. |
| External USDC / USDT send | **Ready** (live; legacy path today) | Customer-scoped facade **coming** |
| Convert USDT↔CAD/EUR, USDT→USD, USD→USDC, EUR→USDC | **Ready** | Same customer; **active** accounts; check quote `limits` |
| GBP OffRamp convert | **Hold** | Until live accept settles |
| Card **issue** (virtual / disposable on active USD) | **Ready** (legacy path today) | Facade **coming** |
| Card **funding** (card-charges into fiat) | **Limited** | Legacy path today; facade **coming**. See [Card funding](/deposit-accounts/card-funding). |

## The flow

<Steps>
  <Step title="Customer vault KYC">
    Create a customer (`pcus_*`), upload documents, submit, wait for `approved`. See [Customer KYC](/deposit-accounts/kyc) and [Customers quickstart](/customers/quickstart).
  </Step>
  <Step title="Deposit-account product gate">
    After `approved`, poll until `products.deposit_account.status=ready` (may pass through `provisioning`). Only then open rails.
  </Step>
  <Step title="Open accounts">
    `POST /partner/customers/{customer_id}/accounts` for fiat and/or stablecoin. Wait until each account is `active`. See [Accounts & deposits](/deposit-accounts/accounts).
  </Step>
  <Step title="Fund and move money">
    Deposit-instructions, [card funding](/deposit-accounts/card-funding), [card issuing](/deposit-accounts/card-issuing), [convert](/deposit-accounts/currency-conversion), [book-transfer](/deposit-accounts/book-transfers), and [sends](/deposit-accounts/sends) remain on **legacy entity paths for existing integrations** until customer-scoped facades ship. New integrators: vault + accounts now; do not build new entity KYC.
  </Step>
</Steps>

## When to use this

| Use this when… | Prefer another product when… |
|----------------|------------------------------|
| Your customer needs reusable **deposit instructions** (bank fields and/or an on-chain wallet) after KYC | They pay **local African fiat** (momo/bank) for a one-shot ramp, see [Quickstart](/quickstart) |
| You key customers by `partner_customer_ref` / `customer_id` and open rails after `deposit_account=ready` | You only need a binding FX quote for a single order (optional `customer_id` on quote when approved) |

## Concepts

| Concept | Meaning |
|---------|---------|
| **Customer** | Your end-customer vault case (`pcus_*`), scoped to your API key, keyed by **`partner_customer_ref`** |
| **Customer status** | `incomplete` → `pending_review` → `approved` \| `rejected` \| `suspended` |
| **Deposit-account product** | `products.deposit_account.status`: `none` \| `provisioning` \| `ready` \| `failed` \| `unavailable` |
| **Account** | A deposit rail on a customer with `deposit_account=ready` (fiat and/or stablecoin) |
| **Fiat account** | e.g. EUR / GBP / USD / CAD when enabled; bank fields when `active` |
| **Stablecoin account** | e.g. USDC or USDT on a stated `network`, with `wallet_address` when ready |
| **Balance** | `balance: { available, current, currency }` when known (may be `null` if refresh fails) |
| **Partner account status** | `pending` until coordinates are usable, then `active` (also `failed` \| `closed`) |

<Note>
Stablecoin rails (e.g. USDC) are **independent ledgers**. They are **not** tied to a USD fiat account balance pot. Open fiat USD and USDC independently as needed.
</Note>

Partners **cannot** register their own wallet as the deposit address. Custody stays on the deposit rail Element Pay provisions.

**Idempotency:** customer create is unique per API key tenant + `partner_customer_ref`. Account open is unique per `(customer, asset_type, currency, network)` (`network` empty for fiat): re-open returns the existing account (`200`); first open returns `201`.

## Status vocabulary

| Object | States |
|--------|--------|
| **Customer** | `incomplete` → `pending_review` → `approved` \| `rejected` \| `suspended` |
| **Deposit-account product** | `none` → `provisioning` → `ready` \| `failed` \| `unavailable` |
| **Account** | `pending` (no usable coords) → `active` (coords usable); also `failed` \| `closed` |
| **Book-transfer** | `pending` \| `completed` \| `failed` (as returned by confirm) |
| **Currency conversion** (order) | `processing` → `settled` \| `failed` |
| **Send** | `processing` → `submitted` → `completed` \| `failed` |

### Check deposit account before opening rails

```bash
curl -sS "$BASE/partner/customers/$CUSTOMER_ID" \
  -H "X-API-Key: $API_KEY" | jq '{
    id: .data.id,
    status: .data.status,
    deposit_account: .data.products.deposit_account
  }'
```

Only when `deposit_account.status == "ready"` call `GET`/`POST` `/partner/customers/{customer_id}/accounts`. If `failed`, `POST …/deposit-account/retry` (best-effort).

### USD readiness (per account)

| Status | Meaning |
|--------|---------|
| `pending` | Open accepted; **no** usable bank coords yet |
| `active` | Coords present; deposit-instructions / convert / issue using that USD can proceed |

**Partner rules**

1. Open may return `201` while still `pending`.
2. Poll `GET …/accounts/{id}` until `status=active`, or wait for **`account.ready`** when that webhook applies.
3. Deposit-instructions while not ready → **422** with hint to poll (legacy path today; customer-scoped facade coming).
4. Card issue on pending or non-USD → **422** (active **USD** fiat only).
5. **KE individuals:** USD bank is **not available**.
6. **Business USD:** often reaches `active`; if it stays `pending`, contact Element Pay admin.

## Webhooks

Configure `webhook_url` (and `webhook_secret`) on your API key. See [Webhooks](/webhooks).

| Event | When |
|-------|------|
| `customer.deposit_account.updated` | Vault deposit-account product status changed (when emitted) |
| `account.opened` | Account open accepted |
| `account.ready` | Usable coordinates (deposit-ready) |
| `account.credited` | Inbound credit settled |
| `account.send.completed` / `account.send.failed` | External wallet send terminal |
| `card_charge.status.changed` | Card **funding** intent |

Prefer **`GET /partner/customers/{customer_id}`** (and customer-scoped account GET) as the source of truth for new integrations. Legacy `entity.*` events may still fire for older entity-based integrations.

## Errors

Same envelope as other Partner APIs ([Errors](/errors)). Do not surface raw upstream payloads to end-users.

## Sandbox notes

- Always read customer `status` and `products.deposit_account` from GET — do not assume auto-approve.
- KE individual **USD** is unavailable; other individual USD may stay `pending`.
- No free USDC / USDT grant in partner APIs. See [Fund an account](/deposit-accounts/accounts#fund-an-account).
