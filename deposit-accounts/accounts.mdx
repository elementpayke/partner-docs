# Accounts & deposits

Open deposit rails on a customer whose **`products.deposit_account.status` is `ready`**. Onboard first via [Customer KYC](/deposit-accounts/kyc) / [Customers quickstart](/customers/quickstart).

<Note>
All calls use `X-API-Key` and `$BASE`. `$CUSTOMER_ID` is a `pcus_*` id with `deposit_account=ready`.
</Note>

<Warning>
Do **not** open accounts via `/partner/entities/…` for new integrations. Use `/partner/customers/{customer_id}/accounts` only.
</Warning>

## Gate: deposit account must be ready

```bash
curl -sS "$BASE/partner/customers/$CUSTOMER_ID" \
  -H "X-API-Key: $API_KEY" | jq '{
    id: .data.id,
    status: .data.status,
    deposit_account: .data.products.deposit_account
  }'
```

| `products.deposit_account.status` | Action |
|-----------------------------------|--------|
| `none` / `provisioning` | Wait / poll |
| `ready` | `GET` / `POST` accounts below |
| `failed` | `POST …/deposit-account/retry`, then poll |
| `unavailable` | Contact Element Pay; do not open accounts |

## Supported rails

| Rail | Currencies | Notes |
|------|-----------|-------|
| **Fiat** | `EUR`, `GBP`, `USD`, `CAD` | Bank deposit coordinates when account `active` |
| **Stablecoin** | `USDC`, `USDT` (with `network`, e.g. `Base` / `Polygon`) | On-chain `wallet_address` when ready |

Opening an unsupported currency returns `422` with the supported list. Currency **conversion** pairs are separate; see [Currency conversion](/deposit-accounts/currency-conversion).

### USD and readiness

| Customer type | USD bank path |
|---------------|----------------|
| **Individual (KE)** | **Not available.** Other fiats and stablecoin rails remain as enabled. |
| **Individual (other)** | **Limited.** Open may succeed while `pending` after deposit product `ready`. Poll until account `active`. |
| **Business** | Often reaches `active`; poll before deposit-instructions or [card issuing](/deposit-accounts/card-issuing). |

**Partner rules (any currency)**

1. Open may succeed with account `status=pending` and null coordinates.
2. Poll `GET …/accounts/{account_id}` until `status=active`, or wait for **`account.ready`**.
3. Deposit-instructions before ready → **422** (customer-scoped deposit-instructions facade is [coming](/customers/quickstart#roadmap); legacy entity path exists for existing integrations only).
4. [Card issuing](/deposit-accounts/card-issuing) requires **active fiat USD** only (legacy path until facade).

## Open accounts (`deposit_account=ready` only)

```bash
# Fiat (example CAD; also EUR, GBP, USD as enabled)
curl -sS -X POST "$BASE/partner/customers/$CUSTOMER_ID/accounts" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "asset_type": "fiat",
    "currency": "CAD"
  }' | jq '.data'

# Stablecoin (USDC or USDT + network)
curl -sS -X POST "$BASE/partner/customers/$CUSTOMER_ID/accounts" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "asset_type": "stablecoin",
    "currency": "USDC",
    "network": "Base"
  }' | jq '.data'
```

Optional: `display_name` (portfolio label only; **not** the bank beneficiary name). `network` applies to stablecoin only.

Account open is idempotent per `(customer, asset_type, currency, network)`: first open `201`; re-open returns the existing account (`200`).

| Call | Purpose |
|------|---------|
| `GET /partner/customers/{customer_id}/accounts` | List rails (with `balance` when known) |
| `GET /partner/customers/{customer_id}/accounts/{account_id}` | One account |

Smoke (staging): list succeeded with multiple rails; sample CAD account included `customer_id`.

## Why you fetch coordinates separately

Opening does **not** always hand usable coordinates immediately. New accounts start `pending` and become `active` when coordinates are ready. Prefer **`account.ready`** or poll GET account.

Typical ready fields: fiat `account_number` (plus `bank_code` / `bank_name` when returned); stablecoin `wallet_address` + `network`.

## Deposit instructions

Customer-scoped `…/deposit-instructions` is on the [roadmap](/customers/quickstart#roadmap). Until that facade ships, existing integrations may still use legacy entity deposit-instructions — **new integrators should not adopt `/partner/entities/*`**. Prefer polling customer-scoped account GET for coordinates when present, or wait for the facade.

When deposit-instructions are available and `status: "ready"`, expect:

| Field | Fiat | Stablecoin |
|-------|------|------------|
| `account_holder_name` | Beneficiary / legal name for bank UX | Present when returned |
| `account_number` | Bank account / IBAN | n/a |
| `bank_code` / `bank_name` | When returned | n/a |
| `wallet_address` / `network` | n/a | Deposit target |
| `chain_disclaimer` | n/a | Show **verbatim** |
| `instructions` | Human copy | Human copy |

<Warning>
**Do not** use account `display_name` as the bank beneficiary. Prefer **`account_holder_name`** from deposit-instructions when present.
</Warning>

If not ready: **422** with message and hint. Never invent or cache stale coordinates.

## Fund an account

| Method | Rail | Status | How |
|--------|------|--------|-----|
| **Bank transfer** | Fiat | Ready when account `active` | Transfer in account currency to bank fields |
| **On-chain transfer** | Stablecoin | **Ready** (with floor) | Matching asset/network to `wallet_address`. Confirm with balance GET and/or **`account.credited`**. |
| **Card funding** | Fiat USD / GBP / EUR | **Limited** | [Card funding](/deposit-accounts/card-funding) (legacy path until facade) |
| **Card issuing** | Fiat **USD** `active` | Ready | [Card issuing](/deposit-accounts/card-issuing); not a funding method for EUR/GBP |

When an inflow **does** settle, you receive **`account.credited`** ([Webhooks](/webhooks)).

Stablecoin caveats:

- Always honor `chain_disclaimer`.
- Small / dust amounts may not credit.
- There is no partner “funding session” / hosted crypto checkout on this surface.

<Note>
**Sandbox:** new accounts start at `0.00`. No free USDC/USDT grant via partner APIs.
</Note>

## What to show end-users

| Account state | UX |
|---------------|-----|
| Customer `deposit_account` not `ready` | "Setting up banking profile" |
| Account `pending` | "Setting up deposit details" |
| Account `active` + bank fields | Show **bank transfer** details |
| Account `active` + `wallet_address` | Show **network + address** + `chain_disclaimer` |
| `account.credited` | Reflect settled inflow / updated balance |
