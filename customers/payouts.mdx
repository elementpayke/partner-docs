# External bank payouts

Send **same-currency fiat** from a customer account to an **outside** bank beneficiary (not another Element Pay ledger account).

| Flow | Destination |
|------|-------------|
| [Book transfers](/customers/book-transfers) | Another account under the same API key |
| **Payout** | External beneficiary bank |
| [Stablecoin sends](/customers/stablecoin-sends) | Crypto wallet |

Prerequisite: [Customers quickstart](/customers/quickstart). Banking gate: `products.deposit_account.status=ready`. Source account must be `status=active` for the payout currency.

<Warning>
**Preview requires available balance** (`available >= amount`). Confirm on live **moves money**. Sandbox often cannot complete a full bank push — use discovery + insufficient-balance checks first.
</Warning>

## Auth

```bash
export BASE="https://sandbox.elementpay.net/api/v1"   # or live base
export API_KEY="is_test_…"                            # or is_live_…
export CUSTOMER_ID="pcus_…"
export ACCOUNT_ID="…"   # fiat account in the payout currency
```

```http
X-API-Key: <API_KEY>
Content-Type: application/json
```

## Integrator flow (recommended order)

Do **not** hardcode bank field lists from this guide alone — call discovery first.

<Steps>
  <Step title="Resolve source account">
    `GET …/accounts` → pick fiat `account_id` with `status=active` and enough `balance.available`
  </Step>
  <Step title="Discover schemes">
    `GET …/payout-methods` → `methods[].scheme`, `required_fields`, `require_one_of`, `aliases`, `default`
  </Step>
  <Step title="Discover banks (local rails)">
    For NGN / GHS / CAD local rails: `GET …/payout-banks` → pick `bank_code` (and `bank_name`)
  </Step>
  <Step title="Preview">
    `POST …/payouts/preview` with `amount`, `beneficiary`, `bank` → `preview_token`
  </Step>
  <Step title="Confirm">
    `POST …/payouts` with `preview_token` + `idempotency_key`
  </Step>
  <Step title="Poll">
    `GET …/payouts/{payout_id}` until terminal status
  </Step>
</Steps>

Use **Try it** under [API Reference](/api-reference) for the same paths (search `payout-methods`, `payout-banks`, then `payouts/preview`).

## 1. Discover schemes

```bash
curl -sS "$BASE/partner/customers/$CUSTOMER_ID/accounts/$ACCOUNT_ID/payout-methods" \
  -H "X-API-Key: $API_KEY" | jq '.data'
```

Typical `data`:

| Field | Meaning |
|-------|---------|
| `currency` | Account currency |
| `methods[].scheme` | Value to send as `bank.scheme` (or omit when `default`) |
| `methods[].required_fields` | Always required on `bank` / beneficiary for that scheme |
| `methods[].require_one_of` | At least one field from each group (e.g. SWIFT: `iban` **or** `account_number`) |
| `methods[].optional_fields` | Truly optional only |
| `methods[].aliases` | Accepted alternate scheme strings (e.g. GHS `eft` → `gh_eft`) |

### Common schemes by currency

| Currency | Schemes (see discovery) | Local bank fields |
|----------|-------------------------|-------------------|
| NGN | `nip` (default), `swift` | `bank_code` + `account_number` + `bank_name` + `country=NG` |
| GHS | `gh_eft` / `eft`, `swift` | `bank_code` + `account_number` + `bank_name` + `country=GH` |
| CAD | `eft` (default), `interac_email`, `interac_account`, `swift` | EFT: institution + transit + account; Interac email: `email` |
| EUR | `sepa` (default), `swift` | SEPA: `iban` + `bank_name` + `country` |
| USD | `ach` / `wire`, `swift` | `routing_number` + `account_number` + … |

**SWIFT:** `required_fields` include `swift_bic`; use `require_one_of: [["iban","account_number"]]` — do not treat both as optional.

**Do not** use corridor [`GET /partner/banks`](/partner/banks) for these codes — that list is for quote `network_id` (African / international corridors), not banking payouts.

## 2. Discover banks (NGN / GHS / CAD)

```bash
curl -sS "$BASE/partner/customers/$CUSTOMER_ID/accounts/$ACCOUNT_ID/payout-banks" \
  -H "X-API-Key: $API_KEY" | jq '.data | {country, currency, n: (.banks|length), sample: .banks[0:3]}'
```

`data.banks[]` typically includes `bank_code`, `bank_name`, and optionally `swift_bic` / `bank_institution_number`. Country is derived from the account currency (`NGN→NG`, `GHS→GH`, `CAD→CA`). Currencies without a directory return `banks: []`.

## 4. Confirm

<Warning>
On **live**, confirm initiates an **external bank payout**. Do not confirm unless you intend to send funds.
</Warning>

```bash
curl -sS -X POST "$BASE/partner/customers/$CUSTOMER_ID/accounts/$ACCOUNT_ID/payouts" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "preview_token": "<from preview response>",
    "idempotency_key": "payout-2026-09-14-001"
  }' | jq '.'
```

Reuse the same `idempotency_key` after network errors. Tokens expire quickly — re-preview if needed.

## 5. Get payout

```bash
curl -sS "$BASE/partner/customers/$CUSTOMER_ID/accounts/$ACCOUNT_ID/payouts/$PAYOUT_ID" \
  -H "X-API-Key: $API_KEY" | jq '.'
```

## Business rules

1. **Same currency fiat → external bank** only (no FX on this rail).
2. **Discover → preview → confirm** on the same source `account_id`.
3. **Balance:** `available >= amount` (exact balance allowed). Insufficient → **422** with `data.available`, `data.amount`, `data.currency`.
4. **Partner-neutral JSON:** errors do not name upstream PSPs.
5. **Fees** may finalize only on confirm/GET — do not invent a fee schedule.

## Funding the source account

| Rail | How the end-customer funds |
|------|----------------------------|
| NGN / GHS / many local fiats | [Deposit instructions](/customers/deposit-instructions) only |
| CAD | Deposit instructions and/or Interac payment-requests (when enabled) |
| EUR / GBP | Deposit instructions and/or Open Banking payment-requests (when enabled) |

NGN has no “request money” payment-request — use deposit coordinates.

## Legacy routes

`/partner/entities/{entity_id}/accounts/.../payouts` remains for old integrations. **New work uses `pcus_*` only.** Discovery (`payout-methods` / `payout-banks`) is customer-scoped only.

## Errors

| Situation | Typical | Action |
|-----------|---------|--------|
| Banking gate not ready | `409` + `banking_profile_incomplete` | Poll `deposit_account` |
| Insufficient balance | `422` + `available` / `amount` / `currency` | Fund via deposit-instructions or lower amount |
| Missing `bank_code` / scheme fields | `422` + `field` | Re-read `payout-methods` / `payout-banks` |
| Preview token expired | `4xx` | Re-preview on the same `account_id` |
